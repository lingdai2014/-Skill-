# KYP Skill · 产品四性 → 客户画像解码器

## 这个 Skill 是什么

KYP 不是产品数据库，而是一台**翻译器**：把产品的客观特征翻译为对客户的价值，再反推应当采集的客户画像维度，最终输出产品与客户的适配度判断。

核心命题：一切「产品好不好」的判断必须以「**对这个客户而言**好不好」为前提；而这取决于产品能给客户带来什么价值。因此 KYP 先回答「产品能为客户带来什么」，再反推「我需要了解客户哪些方面才能下判断」。

三层递进链条贯穿全程：**产品四性 → 客户价值 → 客户画像**。

## 核心知识（必读）

执行任何阶段前，先加载这两份参考文件：

- `references/four-properties.md` —— 产品四性（收益/波动/期限/复杂度）的内涵、衡量维度、客户价值翻译。
- `references/matrix-and-profiles.md` —— 客户五画像详解 + 四性×五画像映射矩阵（核心算法表）。映射矩阵决定「为判断某一性对客户的价值，需要确认哪类画像」。

矩阵符号：★ 主连（核心依赖）　○ 辅连（辅助参考）　— 无显著关联。主连信息必须采集；辅连在主连已采集且无矛盾时可省略，主连出现矛盾信号时回头补全辅连。

## 工作流（四阶段，按需选取）

先判断用户处在哪个场景，再决定从哪个阶段切入——不必每次都跑完四阶段。

| 场景 | 切入点 |
|------|--------|
| 给定一个产品，想知道它的价值/适合谁 | Phase 1 → 2 |
| 已知客户，判断某产品能否推荐 | Phase 1 → 2 → 3 |
| 面访前梳理该补全哪些画像 | Phase 2 输出画像清单即可 |
| 已有完整画像，要出适配结论 | 直接 Phase 3 |
| 要拿可面客的话术 | Phase 4 |

执行前确认手上有什么、缺什么，再开始；不要凭空捏造产品数据或客户画像，缺失项应明确标为「待补全」。

### Phase 1 · 产品价值解码
- **输入**：一个具体金融产品（名称、类型、底层资产、费率、期限、风险等级、历史业绩、风险特征、信息披露材料）。
- **流程**：① 按四性维度填写产品特征字段；② 把每条特征翻译为「对客户意味着什么」（客户价值）；③ 标注每个价值点强弱（强/中/弱）；④ 形成《产品价值卡》。
- **输出**：《产品价值卡》——四性 × 产品特征 × 客户价值翻译。格式见 `references/templates.md`。

### Phase 2 · 价值 → 画像维度映射
- **输入**：产品价值卡 + 4×5 映射矩阵。
- **流程**：① 找出该产品的「主要价值轴」（收益主导/波动主导/期限主导/复杂度主导，常为多轴）；② 在矩阵中查对应画像维度（★主连 + ○辅连）；③ 列出需确认的画像字段清单；④ 标记「客户已有数据」vs「待补全字段」。
- **输出**：《画像确认清单》——按五类画像分组的字段列表 + 优先级。

### Phase 3 · 适配度判断与产出
- **输入**：已采集完整的画像 + 产品价值卡。
- **流程**：① 对每对（产品价值点 ↔ 客户画像项）按 5 分制打适配分；② 按四性汇总——收益/波动/期限/复杂度匹配度；③ 识别「关键不匹配」（如复杂度超出客户认知）；④ 生成《产品-客户适配报告》。
- **铁律**：不符合客户需求的不强推；**任一四性不满足的不推荐**；**客户不理解产品的不推荐**。
- **输出**：《产品-客户适配报告》——分性匹配度评分 + 关键缺口 + 推荐结论（最适合/适合/不建议）+ 理由 + 缓解措施。

### Phase 4 · 沟通建议与话术
- **输入**：待补全画像字段清单（或最适合客户群体）。
- **流程**：① 为每个待补全字段生成自然语言提问（**避免专业术语**）；② 设计「双轨提问」——制度问卷 + 对话式追问；③ 按沟通顺序排序（从轻到重、从客观到主观）；④ 输出可直接面客的问题列表，并点明为客户带来的核心价值（BUL）。
- **输出**：《客户沟通话术清单》。

## 输出规范

四类标准输出物的完整模板见 `references/templates.md`：《产品价值卡》《画像确认清单》《产品-客户适配报告》《客户沟通话术清单》。一个完整的端到端范例（某灵活配置混合型基金）也在该文件中，可作为格式与颗粒度的标杆。

输出时优先用表格承载结构化内容（价值卡、矩阵查询、适配评分），话术清单用分组列表。保持中文金融语境，对客户的价值翻译要具体到「金额×期限×心理感受」，不要停留在抽象形容词。
